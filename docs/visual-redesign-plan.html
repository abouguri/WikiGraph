03 / The central fix

Explicit graph readability rules

  1. Progressive disclosure. Start with the selected entity and at most 12 neighbors. Retain the existing hard ceilings of 40 entities and 120 assertions. Offer “Show more” in controlled batches. Display separate counts for fetched, visible and available connections; page API results as needed. Never imply hidden neighbors do not exist.
  2. Stable topology-aware layout. Prototype deterministic, seeded force positioning with repulsion, link distance and collision constraints. Settle before first display; preserve existing coordinates when expanding. Add nodes near their source and allow only local adjustment. This costs more implementation work than the ellipse but preserves the user's mental map. Do not assume force positioning alone solves labels.
  3. Label budget. Always show the selected node, keyboard-focused node and path labels. Show additional labels only when their measured rectangles fit. Hide lower-priority labels at overview scale; reveal names on hover/focus/tap and in Connections. Resolve placement around the node before shortening. On unavoidable collision, suppress the lower-priority label and make the full name accessible.
  4. Edge hierarchy. Reference links use a quiet dashed stroke; facts use a stronger solid stroke. Arrowheads show direction. The active relation/path gets the strongest contrast; unrelated edges fade but remain distinguishable. Add a wider invisible hit area for selection. Curve reciprocal edges and offer an assertion selector where several records connect the same pair.
  5. Separate inspect from expand. Clicking a node selects it and shows its summary. “Expand connections” is explicit. Clicking an edge opens evidence. Preserve node positions and zoom on selection; only “Focus here” recenters. Add back/reset/fit controls with predictable scope.
  6. Zoom, pan and fit. Constrain zoom; fit includes label bounds and padding. Use resize-aware layout instead of shrinking a fixed SVG. Expose labeled buttons for zoom and reset; drag/pinch is an enhancement, not the only way to operate the graph.
  7. Use a dedicated path view. Show the route as a readable ordered sequence with clear arrows. Hide unrelated edges by default in this mode, with an explicit neighborhood toggle. Each step selects its exact evidence; multiple supporting assertions remain inspectable.
  8. Keep honest semantics. Node size represents selected/context state only, unless a documented metric is later added. No invented clusters, confidence percentages or person/language colors without supported data. Factual coverage is two assertions in the current real corpus; polished visuals must not imply broader extraction success.
Renderer decision: retain SVG for the current 40-node cap so DOM interaction and testing stay straightforward. Isolate layout and label placement from rendering. Evaluate a small layout dependency only if the prototype fails stability or collision gates; document its bundle, licensing and maintenance costs before adoption. A canvas/WebGL rewrite is unnecessary for this size.

4 · Validate

Test realistic density and publish the result

Add deterministic screenshot coverage for the target states and viewports, retain stale-response tests, and measure layout/interaction performance. Complete manual visual checks and the planned three-person usability review when reviewers are available.

Update browser selectors deliberately; rebuild packaged app.js. Replace portfolio screenshots and demo only after the real dense states pass. Commit and push the verified implementation; confirm the resulting Vercel deployment separately.

Tradeoffs: fewer initial nodes improve readability but need explicit disclosure; an on-demand inspector gives the graph room but needs a clear selection affordance; stable force positions take more work but represent topology better; mobile list-first favors readable evidence while keeping the graph one tap away.

06 / Definition of done

Judge the actual application, including its hardest states

  • Viewport: at 1440×900, graph and selection context are usable above the fold; graph canvas target ≥850×600 px. No persistent marketing hero displaces the workspace.
  • Dense graph: a fixed fixture reproduces the screenshot's 40-node / 54-edge scale. No visible label-label overlaps or clipped selected/path labels at default fit. Hidden labels are intentional and recoverable. Add a separate 40-node / 120-edge cap case.
  • Coverage: screenshots at 1440×900, 1280×800, 768×1024 and 390×844 for default, dense, single fact, evidence, long names, path, no results, loading and failure states. Check graph/list view and synthetic badges. Baselines are reviewed, not blindly regenerated.
  • State: selection changes styling and inspector without expanding; expansion is explicit; old responses cannot overwrite newer state. Shared URLs restore the logical view.
  • Mobile: no horizontal page overflow. Search and the primary view are reachable immediately. Full names and source actions remain readable; evidence can be opened and dismissed without losing selection.
  • Accessibility: complete flagship flow without a mouse, including equivalent list actions. Verify focus visibility, overlay focus return, reduced motion, text contrast ≥4.5:1 and essential control/graph contrast ≥3:1. These are checks to perform, not current compliance claims.
  • Performance targets: on recorded reference hardware, layout settles within 300 ms at the 40-node cap and local selection feedback appears within 100 ms. Measure real behavior; report cold API startup separately. Do not equate screenshots with responsiveness.
  • Human review: three people can locate a topic, inspect a source and distinguish a page reference from an extracted fact without coaching. Record friction and fix it; do not mark this gate passed without actual participants.
First implementation priority: compact the workspace and fix the dense graph. Those two changes produce the largest improvement. Font, color and icon polish follow once the information can be read.
